| The public `session-projection` wire-register overload still indexes Host state with a Client key | Retain the exact development-only intersection correction, guarded to alpha.2; strict full typecheck without it fails, even when product-only build passes |
| Official snapshot probes still reproduce equal-size timing misses | Issue #7 remains unresolved; aged fixtures are a test boundary, not a production fix |

## Current Host review follow-up

The upstream findings above remain unchanged. Devwork now awaits a bounded actual-content baseline at round opening and independently compares it with the current checkout across turns. The owned review lists changed files and supplies lazy coarse per-file text/metadata comparisons plus current-side line or whole-file feedback. Unchanged preexisting dirty/untracked content is excluded; baseline paths remain covered after staged/committed deletion. Official summaries are supplemental, not completeness proof. Their absence, expiry, omission or truncation cannot hide changes within the owned capture scope or block owned review. A present summary still must have the correct `cwd` and non-escaping paths, but cannot promote ignored-only paths into owned coverage; net-zero create/delete paths do not block review. This does not patch official code, refresh the user’s index or repair issue #7; the earlier official-snapshot probes are not new cumulative-review test evidence.

Directory-change events preserve the original baseline but invalidate acceptance evidence, current review and prepared feedback, including after a return to the original directory. Version guards reject asynchronous operations spanning a change; a caller-Agent/exact-call-scoped official `tools.guard` rechecks the nested Bash generation after asynchronous permission/pre-execute handling. It does not stop an already-running shell. Briefs, snapshots and batches expose the fixed `integrationRoot`. After restoration, verify again and capture a fresh current review against the retained baseline; a new official diff is not required. These local guards do not implement automatic per-member allocation, enforced isolation or recovery.

The capture requires two matching bounded reads without retries or external-writer locking. Limits remain 10,000 paths, 8 MiB per regular file and 64 MiB total per manifest; new ignored-only paths are excluded, while retained baseline paths stay covered. Symlink leaves use target metadata without following their targets; parent symlinks, submodule directories and unsupported entries refuse capture. See the [current review contract and evidence boundary](headless-poc.md) for details.

Temporary task worktrees retain their detached lifecycle and exact committed Leader summary requirements. The pending-creation reservation blocks replacing a round before asynchronous creation establishes its lease; existing leases also block replacement. Missing or unfinished work remains visible rather than being force-removed. See [task delivery](task-delivery.md).

Headless and Client boundary scenarios exercise published official services with a scripted model. They establish mechanisms, not autonomous Leader judgment, native desktop behavior or sandbox security. Separate alpha.2 probes demonstrated effective-cwd/snapshot misalignment, existing-shell behavior and native worktree retention; they do not establish an upstream repair. See [POC evidence](headless-poc.md) for current regression commands and limits. No release or npm publication is implied.
