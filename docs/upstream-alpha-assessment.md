# Official baseline update — 2026-10-10

English | [中文](upstream-alpha-assessment.zh.md)

The tested baseline is [DSH 0.2.1-alpha.2](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.2), source `d743267388641bc76f17c45ce8b4c231aed1d32c`. Devwork pins its shared DSH peers/development packages to this version; Cordis remains `4.0.5-alpha.1`. It remains a POC, not a stable compatibility promise. Node support remains 24.x only. Install the explicit tested versions rather than relying on moving npm tags.

| Official change/finding | Devwork decision |
| --- | --- |
| Agent/Team dependencies now require the official working-directory service | Inject `workingDirectory`; mount official working-directory dependencies in headless fixtures |
| Effective cwd can differ from immutable `session.header.cwd`; workspace-changes still records the original root | Fix each round’s `integrationRoot` to that original directory and require effective cwd to match; never switch the Leader automatically |
| New Bash uses effective cwd, while an already-running shell keeps its original cwd | Pass the fixed root explicitly to official Bash; do not promise to move existing processes |
| Native `create_worktree` switches the caller, creates a named branch and retains the checkout when switching back | Keep Devwork’s opt-in detached checkout, committed handoff and non-forced cleanup; native creation does not supply delivery ownership, ancestry, summary or acceptance checks |
| Team sends now use the agent inbox; legacy queued-event readers remain | Assert `agent/inbox/spliced` with `source.kind === 'agent-message'`, not new `team/message/queued` emission; inbox acceptance is not processing completion |
| The public `session-projection` wire-register overload still indexes Host state with a Client key | Retain the exact development-only intersection correction, guarded to alpha.2; strict full typecheck without it fails, even when product-only build passes |
| Official snapshot probes still reproduce equal-size timing misses | Issue #7 remains unresolved; aged fixtures are a test boundary, not a production fix |

Directory-change events invalidate acceptance evidence, bound diffs, review snapshots and prepared feedback, including after a return to the original directory. Version guards reject asynchronous operations spanning a change; a caller-Agent/exact-call-scoped official `tools.guard` rechecks the nested Bash generation after asynchronous permission/pre-execute handling. It does not stop an already-running shell. Review and feedback validate official `summary.cwd` and reject paths escaping the root or absent from the existing `git ls-files` fingerprint set, without widening the scanner; briefs, snapshots and batches expose the fixed `integrationRoot`. After restoration, obtain a fresh recorded diff and verify again. These local guards do not implement automatic per-member allocation, enforced isolation or recovery.

The existing public change-event/serial turn-stopping binding remains: passing later verification cannot attach changed code to an old diff, and a truncated summary is rejected. This does not patch official code, refresh the user’s index, fabricate a fallback diff or retry failed snapshots. A nonempty official snapshot can still omit a file; the guards cannot prove completeness. Cumulative round-level review remains pending.

Temporary task worktrees retain their detached lifecycle and exact committed Leader summary requirements. The pending-creation reservation blocks replacing a round before asynchronous creation establishes its lease; existing leases also block replacement. Missing or unfinished work remains visible rather than being force-removed. See [task delivery](task-delivery.md).

Headless and Client boundary scenarios exercise published official services with a scripted model. They establish mechanisms, not autonomous Leader judgment, native desktop behavior or sandbox security. Separate alpha.2 probes demonstrated effective-cwd/snapshot misalignment, existing-shell behavior and native worktree retention; they do not establish an upstream repair. See [POC evidence](headless-poc.md) for current regression commands and limits. No release or npm publication is implied.
