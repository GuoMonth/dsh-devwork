# Task-center domain model

The task is Devwork's durable first-class object. A Session is the task's execution surface, an Artifact records a task output, a PR/MR is an external integration output, and a workspace lease records a resource reservation. Lease metadata alone does not prove actual checkout ownership or authorize deletion.

Each task definition carries a goal, scope, acceptance criteria, dependencies, and an optional parent. A pending task can await Session allocation; once bound, it has exactly one primary Session. Failure, continuation, and retry are recorded as Attempts under that Session; they do not create a second primary Session. The injectable execution engine enforces one active executor; multi-agent collaboration is out of scope.

Task, Session, Artifact, PR/MR integration, and workspace lease states advance independently. An idle Session, stopped Agent, empty child list, or created PR does not mean delivery is complete. The domain prevents completion with unfinished children or a running/waiting Attempt, requires completed dependencies before execution, and rejects cycles across dependencies and child completion ordering. Execution and delivery services must additionally verify acceptance evidence before requesting completion.

`TaskRepository` persists versioned events through an injected `TaskLogStore` and replays them into one projection. `taskTree` adds parent Session links and descendant progress counts without changing task status. The storage boundary accepts `unknown`; unknown fields, invalid sequences, illegal transitions, and cross-task Artifact/Integration links are rejected. Rejected commands do not append events.

`FileTaskLogStore` writes a versioned JSON event log through an exclusive lock, synced temporary file, and atomic rename. The repository serializes its own commands; revision checks reject stale writes from other repositories. Reopening restores data, never Agent execution. Corrupt data is preserved. A lock left by an interrupted write requires explicit inspection; there is no automatic lock stealing, retry, migration, or crash recovery. `MemoryTaskLogStore` provides the same revision contract for tests.

Workspace cleanup belongs to the upcoming delivery service: persist the Artifact and PR/MR reference first, then release the lease only after remote state and acceptance evidence are confirmed. Unknown, dirty, unpushed, unintegrated, or failed cleanup must preserve the workspace. This domain layer records lease transitions but performs no Git, provider, or filesystem cleanup operations. Reserved leases can be released after failed creation; the caller must confirm no owned checkout remains.

The domain and storage foundation is complete, and the task engine (#16) now provides deterministic intake and mockable execution. The Host bridge connects that engine, the panel projection and PR/MR delivery (#18); tests cover transitions, tree/Session mapping, execution outcomes, concurrent writes, restart reads, corrupted data, and failed storage. Mock bridge tests do not prove autonomous task planning or desktop rendering.

The execution layer accepts a strictly validated nested task definition and registers its parent and children in stable order. Each task receives one deterministic primary Session through an injected Session provider; an injected Agent provider executes one task at a time and maps explicit outcomes to durable continue, pause, block, fail, cancel and retry commands. A retry keeps the Session and creates the next Attempt. Per-invocation cancellation signals fence late provider results, and Session provisioning uses a stable idempotency key. This is an injectable engine boundary, not a DSH Host adapter; providers are mockable and no model, desktop service or old Round API is required. Task-tree descendant counts remain progress evidence rather than completion proof.

## Host/Client task panel bridge

`TaskPanelHost` owns one `FileTaskLogStore`/`TaskRepository`, `TaskExecutionEngine`, and `TaskDeliveryService` for the Host lifetime. It injects the public `taskPanelSource`; `forSession(sessionId)` scopes the source to the selected Session while panel and Session views continue reading the same Host projection. Client code only subscribes and renders snapshots, so it does not create a second task store. Host unload and unsubscribe dispose listeners, and a new Host can reopen the same event log without resuming an Agent.

The bridge requires explicit Session/Agent providers and an optional configured delivery provider. With no repository or providers, the source is `unavailable`; it never silently constructs the mock provider. Provider refresh errors retain the previous Artifact/PR state and mark synchronization uncertain through the delivery service. Merge uses `authorizeMerge` and the branded authorization handoff; an Agent or Client boolean cannot authorize it. Workspace cleanup remains behind delivery, acceptance, ownership and clean-delivery checks, so uncertain work and durable Artifacts remain visible.

Creation requires an explicit planner or `createInput` adapter; the bridge does not infer a task from arbitrary Client state.

The current Host tests use mock providers and a memory log. They cover parent/child creation, shared projection, open/continue/view, authorization handoff, source teardown and unavailable configuration. They do not prove autonomous planning, real provider writes, permission UI, or native desktop rendering; those remain real desktop acceptance work.
